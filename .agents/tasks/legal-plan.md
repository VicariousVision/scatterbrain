# Implementation Plan

## Design decisions and data contract

- **Structured DTOs, compatibility wrappers:** Add Pydantic internal-transfer models in `backend/models/content.py`: `SourceSpan`, `ExtractedBlock`, `ExtractedPage`, `ParsedDocument`, `ChunkRecord`, `RetrievedContext`, and citation metadata. `parse_document_structured(...) -> ParsedDocument` and `chunk_parsed_document(...) -> list[ChunkRecord]` become the ingestion contract, while the existing `parse_document(...) -> str`, `clean_text(str) -> str`, `chunk_text(str) -> list[str]`, and `VectorStore.add_document(..., list[str])` entry points remain as compatibility/generic wrappers until every in-repo caller is migrated.
- **Source text remains distinct from embedding context:** Each child stores immutable extracted `raw_text`, cleaned `source_text`, and `embedding_text = breadcrumb + clause identifier/heading + source_text`. The LLM receives the breadcrumb as labeled context beside `source_text`, not spliced into the quoted source, so citations and excerpts remain faithful while embeddings inherit stable hierarchy.
- **Automatic legal/manual routing with generic fallback:** All PDFs are extracted page-by-page, but legal chunking is selected only when a scored detector sees enough manual-title, table-of-contents, section, and nested-clause evidence. Ordinary TXT and unrelated PDFs use the existing generic path backed by LangChain `RecursiveCharacterTextSplitter`; legal overflows may invoke that splitter only after trying legal sub-item, complete-row, and sentence boundaries.
- **Separate parents, vector-ranked children:** Store unembedded parent/intermediate-parent/front-matter records in `document_parents`; keep searchable children in the migrated `document_chunks` table and only child IDs in `vec_chunks`. Stable IDs are deterministic hashes of source SHA-256, normalized logical path/content type, and split or row-group ordinal, so reprocessing identical bytes yields the same parent/child identities without depending on the upload UUID.
- **Additive, idempotent migration:** Preserve `document_chunks`, `vec_chunks`, their existing IDs/content, and `embedding_metadata`; use `PRAGMA table_info` plus additive columns/defaults and a new parent table. Legacy rows are marked `is_structured = 0`, treated as searchable child rows, and retain vectors, but documentation and API metadata state that re-ingestion is required to obtain legal provenance; no migration deletes or rebuilds the configured database.
- **Deterministic hybrid retrieval:** `RetrievalService` asks `VectorStore` for 10 vector candidates, adds deterministic lexical boosts (`+1.0` exact canonical clause identifier, `+0.35` exact amount/BOP code, `+0.20` defined term/acronym), ties by original vector rank then child ID, and selects five while limiting two children per parent and three per section (relaxing limits only to fill the final count). It conditionally fetches continuation neighbors, a short governing excerpt, and canonical cross-reference targets; referenced text is never treated as evidence unless the target child is actually loaded.
- **Backward-compatible API additions:** Keep `ChatResponse.response`, `history`, and integer `retrieved_chunks`, and keep every existing `SearchResultItem` field. Add `citations` and optional structured location fields; old clients continue reading the old fields, while Streamlit renders labels such as `B.4(A)(i), p. 98` (with PDF page fallback).

## Exact configuration contract

`backend/config.py`, `.env.example`, and the configuration tables will use these names and defaults, with Pydantic validation:

| Environment name | Default | Meaning / reconciliation |
| --- | ---: | --- |
| `CHUNK_SIZE` | `1000` | Generic TXT/unrelated-PDF and final recursive fallback size only; align the current code default with the existing README/`.env.example`. |
| `CHUNK_OVERLAP` | `200` | Generic fallback overlap only; never applied between independent legal clauses. |
| `LEGAL_CHUNK_TARGET_CHARS` | `900` | Packing target for searchable legal children. |
| `LEGAL_CHUNK_MIN_CHARS` | `450` | Soft lower bound; intact short provisions/definitions remain valid. |
| `LEGAL_CHUNK_HARD_MAX_CHARS` | `1400` | Strict hard maximum for every searchable legal child; a pathological overlong row remains intact in its unembedded raw parent but is sentence-split into linked children with the header/key repeated. |
| `LEGAL_FORCED_SPLIT_OVERLAP_CHARS` | `120` | Continuity tail used only when one continuous provision reaches sentence/recursive fallback splitting. |
| `LEGAL_PARENT_MAX_CHARS` | `8000` | Above this, create an intermediate logical parent (normally the Roman-numeral provision) rather than expanding a huge governing parent. |
| `RETRIEVAL_CANDIDATE_POOL` | `10` | Child vector candidates fetched before boosts/diversification; validate `>= RETRIEVAL_TOP_K`. |
| `RETRIEVAL_TOP_K` | `5` | Existing setting becomes the final diversified context count and replaces the router’s hard-coded `5`. |
| `RETRIEVAL_MAX_CHILDREN_PER_PARENT` | `2` | First-pass parent diversity cap. |
| `RETRIEVAL_MAX_CHILDREN_PER_SECTION` | `3` | First-pass section diversity cap. |

Validate positive values, `LEGAL_CHUNK_MIN_CHARS <= LEGAL_CHUNK_TARGET_CHARS <= LEGAL_CHUNK_HARD_MAX_CHARS`, forced overlap below the legal target and hard max, candidate pool at least final top-k, and positive diversity limits. Add the already-installed package `langchain-text-splitters==1.1.2` to `backend/requirements.txt`; do not change the project’s existing pinned embedding, pdfplumber, or sqlite-vec versions.
