# Scatterbrain

A local document intelligence system using Retrieval-Augmented Generation (RAG). Upload PDF/TXT documents and query them with natural language. Answers are generated by Ollama and grounded in retrieved document chunks.

## Architecture

**RAG pipeline:**
1. Upload → parse PDF/TXT → chunk text → generate embeddings → store in SQLite + sqlite-vec
2. Query → embed the question → cosine search → retrieve top-k chunks → generate an answer with Ollama

**Tech stack:**
- Backend: FastAPI, Python 3.11+
- Generation: Ollama (local inference)
- Embeddings: Ollama or Hugging Face Sentence Transformers
- Vector store and metadata: SQLite + sqlite-vec
- Document parsing: pdfplumber
- Frontend: Streamlit

## Prerequisites

1. Python 3.11+
2. Ollama, installed from [ollama.com](https://ollama.com/)

Ollama is used for answer generation with the default configuration. Pull the generation model and start the server:

```powershell
ollama pull qwen3.5:0.8b
ollama serve
```

## Setup

Copy the environment template:

```powershell
Copy-Item .env.example .env
```

Install backend and frontend dependencies:

```powershell
cd backend
pip install -r requirements.txt
cd ..\frontend
pip install -r requirements.txt
```

### Embedding provider configuration

The default uses Ollama embeddings:

```dotenv
EMBEDDING_PROVIDER=ollama
OLLAMA_EMBEDDING_MODEL=nomic-embed-text
EMBEDDING_DIMENSION=768
```

Pull the default Ollama embedding model:

```powershell
ollama pull nomic-embed-text
```

To use the Hugging Face `litillabs/litil-embed-0.6b` model instead:

```dotenv
EMBEDDING_PROVIDER=huggingface
HUGGINGFACE_EMBEDDING_MODEL=litillabs/litil-embed-0.6b
HUGGINGFACE_DEVICE=cpu
HUGGINGFACE_NORMALIZE_EMBEDDINGS=true
```

This model returns 1024-dimensional vectors. Scatterbrain detects that dimension automatically and applies the model card's required query instruction (`Instruct: Retrieve text based on user query.\\nQuery: `) to search queries while leaving document text unprefixed. The model is optimized for English, German, and Chinese legal retrieval.

### Changing embedding models

The vector table has a fixed dimension and vectors from different models cannot be mixed. When changing `EMBEDDING_PROVIDER`, `OLLAMA_EMBEDDING_MODEL`, or `HUGGINGFACE_EMBEDDING_MODEL`, delete the database configured by `SQLITE_DB_PATH` and re-ingest documents. Scatterbrain stores the provider/model/dimension metadata and refuses to start with an incompatible existing database.

## Run the application

Backend:

```powershell
cd backend
uvicorn main:app --reload
```

Frontend, in another terminal:

```powershell
cd frontend
streamlit run app.py
```

Backend: `http://localhost:8000`
API docs: `http://localhost:8000/docs`
Frontend: `http://localhost:8501`

## Usage

1. Open the Upload page and upload a PDF or UTF-8 TXT file.
2. Wait for processing to change from `processing` to `completed`.
3. Open Chat and ask questions about the uploaded documents.

The upload pipeline parses, chunks, embeds, and stores the document. The chat pipeline embeds the question, retrieves the most similar chunks, and sends only that context to the Ollama generation model.

## API endpoints

- `POST /documents/upload` — upload a PDF/TXT document
- `GET /documents/` — list documents
- `GET /documents/{id}` — get document status
- `DELETE /documents/{id}` — delete a document and its chunks
- `POST /chat/query` — query documents with RAG
- `GET /health` — service health check

## Configuration

| Setting | Default | Description |
|---|---|---|
| `EMBEDDING_PROVIDER` | `ollama` | `ollama` or `huggingface` |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama server URL |
| `OLLAMA_MODEL` | `qwen3.5:0.8b` | LLM used for answer generation |
| `OLLAMA_EMBEDDING_MODEL` | `nomic-embed-text` | Ollama embedding model |
| `EMBEDDING_DIMENSION` | `768` | Ollama vector dimension |
| `HUGGINGFACE_EMBEDDING_MODEL` | `litillabs/litil-embed-0.6b` | Hugging Face model ID/path |
| `HUGGINGFACE_DEVICE` | `cpu` | Sentence Transformers device |
| `HUGGINGFACE_NORMALIZE_EMBEDDINGS` | `true` | Normalize Hugging Face vectors |
| `SQLITE_DB_PATH` | `scatterbrain.db` | SQLite database path |
| `CHUNK_SIZE` | `1000` | Characters per chunk |
| `CHUNK_OVERLAP` | `200` | Chunk overlap |
| `RETRIEVAL_TOP_K` | `5` | Chunks retrieved per query |

## Troubleshooting

**Hugging Face model loading fails:** verify `sentence-transformers` was installed from `backend/requirements.txt`, check the model ID, and ensure the first-run machine can download the model. A local model directory can also be used as `HUGGINGFACE_EMBEDDING_MODEL`.

**Embedding configuration does not match the database:** delete the database configured by `SQLITE_DB_PATH`, then upload the documents again.

**Ollama is unavailable:** make sure `ollama serve` is running, check `OLLAMA_BASE_URL`, and verify the generation model with `ollama list`.

**No chunks are produced:** check that the PDF contains selectable text or that TXT input is UTF-8 encoded.
